2.Viết lệnh thực hiện gộp nhánh bug vào nhánh feature sử dụng git merge

git checkout feature
git merge bug

3. Viết lệnh thực hiện gộp nhánh feature vào bug sử dụng git rebase
git checkout bug
git rebase feature

4. Phân biệt git merge và git rebase(giống, khác nhau, khi nào nên sử dụng)
- Giống: +đều gộp nhánh dc.
	+đều cho ra kết quả giống nhau
	+
- Khác: git merge: + có commit merge mới xuất hiện
	git rebase: + không có commit mới xuất hiện
			+ xóa luôn những commit ở nhánh cũ (những commit này đã nhảy qua nhánh mới)
			
- khi nên sử dung:+ merge dung trong TH ít nhánh (vì tạo ra quá nhiều commit merge làm xấu tree )
		+ rebase dung trong TH nhiều nhánh (vì k tạo ra commit gộp nhánh, dễ tìm thấy hash-commit) 
5. Phân biệt git fetch và git clone

git fetch: dung de cập nhật dữ lieu mới nhất từ remote repo
git clone: dung de liên kết local repo và remote repo

6. Phân biệt git fetch và git pull

git fetch: dung de cập nhật dữ lieu mới nhất từ remote repo nhưng giữ nguyên nhữnggi dc lấy về
git pull: dung de cập nhật dữ lieu mới nhất từ remote repo nhưng merge các commit mới từ máy khác và commit từ local để k sinh ra conflict khi push lên remote repo

7. Phân biệt git pull và git pull --rebase

git pull: dung de cập nhật dữ lieu mới nhất từ remote repo nhưng merge các commit mới từ máy khác và commit từ local để k sinh ra conflict khi push lên remote repo
git rebase: cũng giống pull nhưng thay vì merge thì dung rebase nên k sinh ra commit merge khó nhìn tree.

8. Git log dùng để làm gì : xem lịch sử commit

9. Git status dùng để làm gì: xem trạng thái của file mới (untracked) hoặc thay doi cua những cái mình làm

10. Git add dùng để làm gì: dua những thay doi hay file mới(untracked) vào staged

11. Git commit dùng để làm gì: dua những thay doi hay newfile vào unmodified

14. Mô tả lệnh để xóa branch ở remote: ta lên remote repo, chọn vào setting nhánh cần xóa và xóa (nếu duoc cấp quyền)
15. Nhánh trung gian là gì, mục đích của nhánh trung gian: 
- Nhánh trung gian là nhánh duoc fetch về từ remote repo (nếu remote repo dã tạo nhánh dó rồi), nhánh này là READABLE, chúng ta không chuyển HEAD sang nhánh này duoc. 
- Mục dích: nhánh này có nhiệm vụ fetch/pull từ remote repo về local và push lên lại remote repo.
16. Detach HEAD là gì: 
- là khi ta checkout sang 1 commit cha nào dó và tạo ra 1 commit mới thì commit này sẽ không hiện lên tree khi git log, làm cho ta mất code.
17. Phân biệt HEAD và BRANCH: 
- HEAD: là working directory hiện tại ma ta dang lam viec, head o dau ta lam viecở đó.
- Branch: khi muốn làm 1 task, thì phải coi task dó thuộc branch nào ta checkout qua chính xác branch dó de làm việc.
- Branch thì có nhiều, nhưng HEAD chỉ có 1.

19. Liệt kê các trạng thái của file trong git, giải thích từng trạng thái:
-untracked: file mới chua qua staged de vào unmodified
-modified: từ unmodified thay doi hoặc từ staged restore về
- staged: duoc add vào khiở modified hoặc untracked hoặc restore từ unmodified
- unmodified: được commit từ staged.
20. Mô tả các bước cần thực hiện khi nhận 1 task từ dự án, cho ví dụ:
- Xem task đóở version nào 
- version dó o branch nào
- sau đó fetch về (local repo phai dc lien ket vs remote repo)
- Tạo 1 nhánh từ nhánh trung gian của remote branch đó
- chuyển HEAD qua nhánh dó.
- Code trên nhánh dã tạo
- add, commit, push lên chính xác remote branch
Ví dụ: Tạo file sum1.1.
- fetch toan bo về
- tạo 1 nhánh t1-sum1.1 từ origin/todo-app-1.0
- chuyển HEAD qua t1-sum1.1
- Code, add, commit
- push lên từ nhánh t1-sum1.1 den todo-app-1.0: git push origin t1-sum1.1 todo-app-1.0
21. Git cherry-pick sử dụng để làm gì: de lay 1 commit từ 1 nhánh nào do chuyen sang nhánh vị trí mà bạn muốn khi ta commit hoặc gộpở nhánh mà ta k muốn.
