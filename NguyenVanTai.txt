3. Viết lệnh thực hiện gộp nhánh feature vào bug sử dụng git rebase
git checkout bug
->git rebase bug
4. Phân biệt git merge và git rebase(giống, khác nhau, khi nào nên sử dụng)
git merge: gộp nhánh , giữ lịch sử phân nhánh,có tạo commit gộp, ít xảy ra conflict,dễ làm với ít Nhánh
git rebase: duy chuyển commit hiện tại lên trước một commit khác, giúp lịch sử commit sạch sẽ dễ nhìn hơn
Giống nhau: đều gây ra conflict, đều gộp giúp nhánh hiện tại cập nhật đầy đủ commit
5. Phân biệt git fetch và git clone
->Git fetch để đồng bộ, lấy các cập nhật mới nhất từ remote về local
->Git clone thì sẽ lấy toàn bộ lịch sử commit , đồng thời tạo một thư mục mới trùng với tên repository
và kết nối với repo gốc(origin)
6. Phân biệt git fetch và git pull
->git fetch lấy các dữ liệu mới nhất từ remote về(Đồng bộ), không thay đổi nhánh hiện tại
->git pull là bao gồm cả git fetch + git merge: có nghĩa lấy mới nhất từ remote về(đồng bộ), sau đó thực hiện gộp(merge)
vào nhánh HEAD đang trỏ tới(đang đứng).

18. Có mấy cách để xóa commit, mô tả và cho ví dụ
->sử dụng git reset --soft HEAD~n: cái này giúp xóa commit gần con trỏ HEAD đồng thời đưa các commit vào staging area.
ví dụ +git reset --soft HEAD~1: lùi lại 1 commit trước commit hiện tại(HEAD đang trỏ tới)
sử dụng git reset --hard HEAD~n: cái này giúp xóa hoàn toàn mọi thay đổi , không giống như --soft nó xóa sạch file và các thay đổi ở commit đó.
->git rebase -i HEAD~n
ví dụ git rebase -i HEAD~2:lùi lại 2 commit tính cả commit hiện tại,
sau đó hiện lên Vim, nhấn i để chỉnh sửa
pick 906afef version 7
pick 5b34c10 version 8
ví dụ ở đây có hai commit thì muốn sửa commit version 7 thì làm như sau
edit 906afef version 7
pick 5b34c10 version 8
sau đó dùng git commit --amend và điền lại message theo mong muốn 
sau đó nhấn git rebase --continue nữa là hoàn thành,
->sử dụng git commit --amend -m "message update".
Lệnh này có tác dụng khi mà bạn muốn thay đổi commit mà con trỏ HEAD đang trỏ tới
