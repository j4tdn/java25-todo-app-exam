3. Viết lệnh thực hiện gộp nhánh feature vào bug sử dụng git rebase
-> git checkout bug

4. Phân biệt git merge và git rebase(giống, khác nhau, khi nào nên sử dụng)
-> -Giống: gộp nhánh cần gộp vào nhánh hiện tại, cập nhật dữ liệu nhánh gộp vào nhánh hiện tại, có thể gây conflict
-Khác:  +Merge:
		Tạo ra commit mới
		Lịch sử bị rẽ nhánh, rối
		Giữ nguyên lịch sử commit
		Dễ dùng, ít gây conflict
		
	+Rebase:
		Thay đổi hash commit
		Lịch sử thẳng nhánh, dễ nhìn
		Rút gọn lịch sử commit
		Phức tạp, nhiều conflict
-Nên sử dụng:
	+Merge: nếu muốn giám sát hoàn toàn quy trình làm, phù hợp cho người mới
	+Rebase: nếu muốn lịch sử commit rõ ràng, sạch

5. Phân biệt git fetch và git clone
->-Giống:
	+Đều tương tác với remote repo
	+Cập nhật dữ liệu về local repo
	+Đều cần mạng
-Khác:
	+Clone:
		Tải dữ liệu lần dầu về local
		Sao chép toàn bộ dữ liệu
		Tạo thư mục mới
		Không gây xung đột
		Không cần merge, rebase
	+Fetch:
		Cập nhật dữ liệu về local
		Cập nhật các commit, branch
		Không bị thay đổi code
		Có thể gây xung đột
		Có thể cần merge, rebase

6. Phân biệt git fetch và git pull
->-Giống:
	+Đều tương tác với remote repo
	+Cập nhật dữ liệu về local repo
	+Đều cần mạng
	+Có thể gây xung đột
	+Cập nhật các commit, branch
	+Không bị thay đổi code

-Khác:
	+Pull:
		git pull = git fetch + git merge
		Cập nhật dữ liệu về local và tự động merge
	+Fetch:
		git fetch
		Cập nhật dữ liệu về local
		Có thể cần merge, rebase

7. Phân biệt git pull và git pull --rebase
->-Giống:+Đều tương tác với remote repo
	+Đều cần mạng
	+Có thể gây xung đột

-Khác:  +Git pull:
		Tạo ra commit mới
		Lịch sử bị rẽ nhánh, rối
		Giữ nguyên lịch sử commit
		Dễ dùng, ít gây conflict
		git pull = git fetch + git merge

	+git pull --rebase:
		Thay đổi hash commit
		Lịch sử thẳng nhánh, dễ nhìn
		Rút gọn lịch sử commit
		Phức tạp, nhiều conflict
		git pull = git fetch + git rebase

15. Nhánh trung gian là gì, mục đích của nhánh trung gian
-> Là nhánh được tạo ra tạm thời để hợp nhất, phát triển, xử lí xung dột với các nhánh chính
Mục đích: để không bị ảnh hưởng đến các nhánh chính, có thể rollback

16. Detach HEAD là gì
->là trạng thái HEAD trỏ trực tiếp đến commit

17. Phân biệt HEAD và BRANCH
->HEAD: con trỏ dại diện cho vị trí hiện tại trong lịch sử commit, chỉ có một HEAD, không thể tạo, không có merge hay rebase
BRANCH: con trỏ đại diện cho chuỗi commit, quản lý luồng công việc, có thể có nhiều branch, có thể tạo, có thể có merge hay rebase

18. Có mấy cách để xóa commit, mô tả và cho ví dụ
-> git reset --soft HEAD~n(xóa sau merge
git reset --hard HEAD~n(Xóa mạnh dù merge hay chưa
n là số commit xóa
Ví dụ: Xóa 3 commit gần đây từ commit mới nhất
git reset --soft HEAD~3
git reset --hard HEAD~3

19. Liệt kê các trạng thái của file trong git, giải thích từng trạng thái
->-Untracked: file lần dầu xuất hiện, chưa được quản lý bởi git
-Modified: file đã được chỉnh sửa nhưng chưa được add
-Unmodified: file chưa được chỉnh sửa gì từ lần commit gần nhất
-Staged: file đã add đang chờ để commit

20. Mô tả các bước cần thực hiện khi nhận 1 task từ dự án, cho ví dụ
->-B1: Xác định chức năng đó thuộc version nào
-B2: Xác định branch nào đại diện cho version đó
-B3: git fetch
-B4: Tạo nhánh từ nhánh trung gian
-B5: code, add, commit, push
Ví dụ: nhận task làm chức năng kiểm tra số dối xứng ở version todo-app-2.0
-B1: Xác định chức năng đó thuộc version todo-app-2.o
-B2: version đó do branch todo-app-2.0 đại diện
-B3: git fetch
-B4: Tạo nhánh từ nhánh trung gian origin/todo-app-2.0
-B5: code, add, commit, push
